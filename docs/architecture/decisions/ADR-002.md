# ADR-002: Database Choice for the Parking System

**Status:** Accepted  
**Date:** 2025-09-27  

## Context
- **FR-001**: fast display of available parking spots on the map.  
- **FR-003, FR-006**: convenient data management and backup.  
- **NFR-001**: list display time ≤ 3 seconds.  
- **NFR-002**: secure storage of passwords and payment data.  
- **NFR-003**: reliability and regular backups.  

## Decision
Use **PostgreSQL** as the main database for the system.  

- Supports JSON fields for flexible data (e.g., parking lot settings).  
- Compatible with backup and scaling mechanisms.  

## Consequences
- ✅ Reliable storage of relational data and transaction history.  
- ✅ Full compatibility with all Django features.  
- ✅ Ability to perform complex queries and analytics.  
- ⚠️ Requires configuration of backup and performance monitoring.  
- ❌ PostgreSQL is less flexible for document-oriented structures than MongoDB, but this is not critical for the system.  

## Considered Alternatives
- **MongoDB** — rejected because the data structure is strictly relational, and integration with Django is more complex.  
- **MySQL** — rejected due to lower compatibility with certain Django features and more complex analytical queries.
