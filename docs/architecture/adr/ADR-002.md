# ADR-002: Вибір бази даних для системи паркування

**Статус:** Прийнято  
**Дата:** 2025-09-27  

## Контекст
- **FR-001**: швидке відображення вільних паркомісць на карті. 
- **FR-003, FR-006**: зручне управління даними та резервне копіювання.  
- **NFR-001**: час відображення списку ≤ 3 сек.  
- **NFR-002**: безпечне зберігання паролів та платіжних даних.  
- **NFR-003**: надійність та регулярні резервні копії.  

## Рішення
Використовувати PostgreSQL як основну базу даних для системи.  

- Підтримка JSON-полів для гнучких даних (наприклад, налаштування паркінгів).  
- Сумісність з резервним копіюванням та масштабуванням.  

## Наслідки
- ✅ Надійне зберігання реляційних даних та історії транзакцій.  
- ✅ Підтримка всіх функцій Django без обмежень.  
- ✅ Можливість виконання складних запитів та аналітики.  
- ⚠️ Потрібне налаштування резервного копіювання та моніторингу продуктивності.  
- ❌ PostgreSQL менш гнучке для документо-орієнтованих структур, ніж MongoDB, але це не критично для системи.  

## Розглянуті альтернативи
- **MongoDB** — відхилено, бо структура даних чітко реляційна, а інтеграція з Django складніша.  
- **MySQL** — відхилено через меншу сумісність з деякими функціями Django та складніші аналітичні запити.
