# ADR-001: Architecture for the Parking System

**Status:** Accepted  
**Date:** 2025-09-28  

## Context
- **FR-001**: display available parking spots on the map.  
- **FR-002**: integration with payment services.  
- **NFR-001**: list display time ≤ 3 seconds.  
- **NFR-004**: adaptive interface.  

## Decision
Use a **multilayer architecture** (frontend ↔ backend ↔ database):

## Consequences
- ✅ Separate scalability for frontend and backend (possible to add mobile app support or expand databases without major changes).  
- ✅ Easy functional expansion (new services).  
- ⚠️ A load balancer is required under high traffic.  
- ❌ Additional network delay (but within NFR-001 limits).  

## Considered Alternatives
- **Monolith** — rejected (hard to scale).  
- **Serverless** — rejected (complex integration with payment services).
